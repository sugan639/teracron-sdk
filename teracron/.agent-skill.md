# Teracron SDK — Agent Skill Reference (Root)

> Quick reference for AI agents (Cursor/IDE-embedded) interacting with the
> Teracron Python SDK from the **terminal**.
> For the full tracing reference, see `teracron/tracing/.agent-skill.md`.

---

## What this lets an AI agent do

When a user says *"I got a Teracron alert that my payment server crashed at
3 AM — find out what happened"*, the agent (which may know nothing about the
payment server) can diagnose it entirely from the terminal:

1. Confirm the user is **logged in** to Teracron in their terminal (like Convex).
2. **List the projects** the key can access and pick the right one (e.g. payment).
3. **Search** the project for the crash (failed events around the reported time).
4. Pull the **trace / thread-flow** — the exact method-call hierarchy, where it
   failed, the error, and the captured input values (non-captured values appear
   as `#redacted`).
5. Map the failing span's `operation` + `captured_params` back to the source
   code (the agent is assumed to have the codebase open) and propose a fix.

---

## CRASH-DIAGNOSIS PLAYBOOK (follow in order)

```bash
# 0. Are we authenticated? (offline-safe check)
teracron-agent whoami --json
#    └─ if not authenticated → tell the user to run:  teracron-agent login

# 1. Discover the project this key maps to (find the slug, e.g. "payment")
teracron-agent projects --json
#    └─ a Teracron API key is project-scoped → returns exactly one project.
#       Note its "slug" and "name" — you reference the slug implicitly via the key.

# 2. Search for the crash — recent FAILED workflow events
teracron-agent events --status=workflow_failed --limit=20 --json
#    └─ optionally narrow by workflow:  --workflow=payment
#    └─ optionally bound the time:      --since=2025-07-22T02:30:00Z
#    Pick the failed event whose timestamp matches the reported incident (~3 AM).
#    Grab its "trace_id".

# 3. Pull the full thread-flow (parent → child span tree) for that trace
teracron-agent trace <TRACE_ID> --json
#    └─ this is the method-calling flow as a single logical thread:
#       which methods ran, in what order, timing, status, error, and params.

# 4. (optional) Replay the failure locally to reproduce / generate a repro script
teracron-agent simulate <TRACE_ID> --format=markdown
teracron-agent simulate <TRACE_ID> --format=script > repro.py
```

### How to read the trace (step 3 output)

- Walk the spans by `parent_span_id` (root has `parent_span_id: null`).
- The span with `status: "failed"` deepest in the tree is usually the root cause.
- `operation` is the fully-qualified function name → grep the codebase for it.
- `captured_params` holds the *whitelisted* input values at failure time.
  A value of `"#redacted"` means the argument existed but was intentionally not
  captured (PII boundary) — do NOT treat it as the literal cause.
- `error_type` + `error_message` give the exception. Combine with `captured_params`
  to explain *why* it failed (e.g. `amount=-5` → `ValueError`).

## Local / Direct mode (no inter-server HTTPS)

In local development the SDK does **not** talk to `teracron.com`. Instead it
posts to a **local interface** — a loopback stand-in for `teracron.com` — over
plain HTTP. The local Teracron consumes what that interface spools.

```
  payment.py ──http──▶ local interface (loopback:3000) ──spool──▶ local Teracron
    (SDK)               teracron-agent local-interface       ~/.teracron/local-spool/
```

Start the interface in its own terminal:

```bash
teracron-agent local-interface            # listens on 127.0.0.1:3000
teracron-agent local-interface --port 4000
```

Point the SDK / CLI at it with a **loopback** domain. Loopback hosts are special-cased:

- scheme becomes `http://` automatically (no TLS on the local hop), and
- the host is allowed **without** `TERACRON_ALLOW_CUSTOM_DOMAIN` (loopback only).

```bash
teracron-agent --domain localhost:3000 projects --json
teracron-agent --domain localhost:3000 events --status=workflow_failed --json
export TERACRON_DOMAIN="localhost:3000"   # or set it once
```

> Payloads stay RSA+AES encrypted regardless of scheme, so dropping TLS for the
> loopback hop never exposes plaintext. The relaxation is loopback-exact — it
> does NOT apply to any other host, preserving production SSRF/TLS protection.

## CLI Commands

| Command | Description |
|---|---|
| `teracron-agent` | Run metrics agent (default) |
| `teracron-agent run` | Run metrics agent (explicit) |
| `teracron-agent login` | Authenticate and store API key |
| `teracron-agent logout` | Wipe stored credentials |
| `teracron-agent whoami` | Show current auth status |
| `teracron-agent projects` | List accessible project(s) — discovery step |
| `teracron-agent events` | Query recent workflow events (crash search) |
| `teracron-agent workflows` | List workflow run summaries |
| `teracron-agent trace <id>` | Fetch a full trace / thread-flow span tree |
| `teracron-agent simulate <id>` | Replay a failed trace locally |
| `teracron-agent curl-example` | Print curl command examples |
| `teracron-agent local-interface` | Run the local loopback interface (dev) |

All query commands support `--json` (machine-readable) and `--api-key` (override).
All commands support `--domain` (e.g. `--domain localhost:3000` for local mode).

## Curl Access (for AI Agents)

The REST base path is `/api/v1`. Use `https://` for production and `http://`
for the local interface (loopback). Run `teracron-agent curl-example` to get
ready-to-paste commands pre-filled with the correct base URL.

```bash
export TERACRON_API_KEY="tcn_..."
BASE="https://www.teracron.com/api/v1"        # local: http://localhost:3000/api/v1

# Discover the project (find the slug)
curl -s -H "Authorization: Bearer $TERACRON_API_KEY" "$BASE/projects"

# Search for the crash (failed events)
curl -s -H "Authorization: Bearer $TERACRON_API_KEY" \
  "$BASE/events?status=workflow_failed&limit=10"

# Pull the thread-flow for a trace
curl -s -H "Authorization: Bearer $TERACRON_API_KEY" \
  "$BASE/traces/<TRACE_ID>"

# Workflow summaries
curl -s -H "Authorization: Bearer $TERACRON_API_KEY" \
  "$BASE/workflows?limit=20"

# Single span detail
curl -s -H "Authorization: Bearer $TERACRON_API_KEY" \
  "$BASE/spans/<SPAN_ID>"
```

> NOTE: All query endpoints live under `/api/v1` (not `/v1`). Bearer auth is
> project-scoped, so `/api/v1/projects` returns the single project bound to the
> key — selecting "the payment project" means authenticating with its key.

## Capturing input values + `#redacted`

`@trace("payment", capture=["a", "b"])` records the *values* of the named args
with the span. To additionally record that *other* args existed (without their
values), opt in to redaction:

```python
@trace("payment", capture=["amount"], redact_uncaptured=True)
def charge(amount, card_number):
    ...
# span.captured_params → {"amount": 99.99, "card_number": "#redacted"}
```

Default (`redact_uncaptured=False`) keeps the original minimal footprint — only
whitelisted params appear at all.
